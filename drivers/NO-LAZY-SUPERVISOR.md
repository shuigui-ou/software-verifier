# 不偷懒监督器（插件）· 使用说明

> 接入对象：**software-verifier**（本目录）
> 文件：`drivers/no-lazy-supervisor.cjs`
> 零依赖 · CommonJS · 单次判定 **0.005ms**

---

## 它是什么

监督 AI 是否「偷懒」，并把检出的问题**转发到宿主既有的 P/I 类通道**，进内核账本与审计链。

**不重复造轮子**：宿主已有 `tapPlan`（计划偏离）与 `tapHanging`（悬挂未完结），
内核也已有 `plan` / `thread` 两本账。本插件只做**自动检测**——
把那些原本要靠人或宿主自觉上报的问题，改成每轮自动比对并上报。

发明新通道 = 绕过宿主内核的审计与账本，属于破坏而非增强。

---

## 快速开始

```js
const sup = require('./drivers/no-lazy-supervisor.cjs');
const host = require('./evolution-host.cjs');

host.init({});                     // 宿主内核初始化（未初始化也不影响插件运行）

// 每轮对话后调用
const r = sup.watchTurn({
  reply:     aiResponse,                        // 必填：AI 本轮回复
  prevReply: lastResponse,                      // 可选：上一轮（用于趋同化检测）
  contract:  ['问题分析', '修改方案', '完整代码'],// 可选：任务契约锚点
  taskId:    'task-123',
});

// r.ok       —— 是否正常执行（恒不抛错）
// r.flagged  —— 检出哪些偷懒 [{type, reason, missing?}]
// r.report.reported — 是否已上报内核（含 signalId / ledgerId）
```

**宿主未 init 也能跑**：此时只本地记录、不上报，返回 `reason:'host_not_ready'`。

## 检出四类（有机械判据）

| 类型 | 判据 | 映射通道 |
|---|---|---|
| **contract** 契约未完成 | 任务要求 N 项，回复缺某些锚点 | P 类（plan 账本）|
| **promise** 承诺未兑现 | 说了「稍后/接下来」，但本轮无实质产出 | I 类（thread 账本）|
| **repetition** 趋同化 | 与上一轮 2-gram 相似度 ≥ 0.6 | P 类 |
| **filler** 免责搪塞 | 泛泛句式 + 全文无具体产出 | P 类（**默认关闭**）|

### ⚠ 明确不做的

**不判断回答质量。**「太浅」「不够深入」「没说到点子上」没有客观阈值，
试图量化它只会注入主观偏见。这类问题需要 LLM-as-judge 或人工。

---

## 配置

```js
sup.configure({
  repetitionThreshold: 0.6,   // 趋同化相似度阈值
  enableFiller: false,       // 免责搪塞检测（默认关闭，易误伤）
  autoReport: true,          // 是否自动上报内核
  maxReportPerTurn: 2,       // 单轮最多上报几条，防刷屏
});
```

`sup.analyze(...)` 是 dry-run：只检测不上报，用于评估误伤率。

## 三个实测踩出的坑（照着做能省你重踩）

### ① 「有产出」不能只看是否提到动作词

「稍后我会把完整的**分析**报告发给你」含"分析"，但那只是承诺里提到报告，
**本轮一个字都没干**。

判据是「长度 ≥50 字 **且** 含数字/代码/列表结构」，不是"出现了动作词"。

### ② 长度门槛 80 字太死

一段 76 字的「三条结论」会被误判成没干活。现为 50 字。

### ③ 「诚实澄清」不是「免责搪塞」

模型说：

> 「请把代码贴出来，目前消息中没有看到代码。」

表面像搪塞，实际是**诚实且正确**的行为。故 `filler` 检测会识别澄清标记并豁免，
这条已写成测试断言（`E 诚实澄清不得被拦`），防止未来被"优化"掉。

**把这类区分错当偷懒，比漏检更糟**——那等于训练出一个遇事就硬编答案的 AI。

## 验收

```bash
node drivers/no-lazy-supervisor.test.cjs
```

```
通过 20 项，失败 0 项
```

覆盖：畸形输入不抛错 / 四类检出 / 三类不误伤 / **真进宿主账本与审计链** / 性能。

其中「认真作答 → 不产生任何上报」这一项专门验证**不污染宿主账本**——
监督器只记录真问题，不制造噪声。

---

## 红线：绝不干扰宿主

与宿主 `tap*` 一致，本插件**任何内部异常都被吞掉**，返回
`{ok:false, reason:'supervisor_error'}`，绝不 throw。

监督器出问题，不能让被监督者崩溃。
